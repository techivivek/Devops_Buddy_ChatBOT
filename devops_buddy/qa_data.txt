# --- BASIC TO INTERMEDIATE DEVOPS QUESTIONS ---

Q: What is DevOps?
Q: Define DevOps
Q: Can you explain DevOps?
Q: DevOps meaning
A: DevOps is a cultural and technical movement that combines software development (Dev) and IT operations (Ops) to shorten the development lifecycle and provide continuous delivery with high software quality. It bridges the gap between development and operations teams through collaboration, automation, and shared responsibility.

Q: What are the key principles of DevOps?
Q: Core principles of DevOps?
Q: DevOps fundamentals
A: The key principles of DevOps include:
1. Collaboration between Dev and Ops teams
2. Automation of repetitive tasks
3. Continuous Integration (CI)
4. Continuous Delivery/Deployment (CD)
5. Infrastructure as Code (IaC)
6. Monitoring and logging
7. Feedback loops for continuous improvement

Q: What is the difference between Agile and DevOps?
Q: Agile vs DevOps
Q: Compare Agile and DevOps
A: While Agile focuses on iterative development and customer feedback, DevOps extends Agile by:
- Bridging the gap between development and operations
- Emphasizing automation throughout the SDLC
- Focusing on operational aspects in production
- Implementing CI/CD pipelines
- Prioritizing monitoring and reliability

Q: Explain the DevOps lifecycle
Q: DevOps process flow
Q: Stages of DevOps
A: The DevOps lifecycle consists of 8 key stages:
1. Plan: Define requirements and track progress
2. Code: Version control and peer reviews
3. Build: Compile and package code
4. Test: Automated testing at multiple levels
5. Release: Prepare for deployment
6. Deploy: Automated rollout to environments
7. Operate: Manage production infrastructure
8. Monitor: Track performance and user behavior

# --- DEVOPS TOOLS & USAGE ---

Q: What is Jenkins?
Q: Use of Jenkins?
Q: Jenkins in CI/CD
A: Jenkins is an open-source automation server that:
- Supports building, testing, and deploying software
- Offers 1600+ plugins for integration
- Enables pipeline-as-code with Jenkinsfile
- Provides distributed builds across multiple nodes
- Supports various version control systems

Q: What is Docker?
Q: Use of Docker in DevOps?
Q: Containerization benefits
A: Docker is a containerization platform that:
- Packages applications with dependencies into containers
- Ensures consistency across environments
- Uses lightweight virtualization
- Supports microservices architecture
- Enables efficient resource utilization
- Integrates with orchestration tools like Kubernetes

Q: What is Kubernetes?
Q: Why use Kubernetes?
Q: K8s benefits
A: Kubernetes is an open-source container orchestration platform that:
- Automates deployment, scaling, and management
- Provides self-healing capabilities
- Enables load balancing and service discovery
- Supports rolling updates and rollbacks
- Works across on-prem and cloud environments
- Manages storage orchestration

Q: What is Ansible?
Q: How does Ansible help in DevOps?
Q: Configuration management tools
A: Ansible is a simple yet powerful configuration management tool that:
- Uses YAML for playbooks (human-readable automation)
- Operates agentlessly (uses SSH)
- Supports idempotent operations
- Provides modules for cloud, containers, and networking
- Enables infrastructure as code
- Simplifies complex workflows

# --- CI/CD PIPELINES ---

Q: What is CI/CD?
Q: Define Continuous Integration and Continuous Deployment
Q: CI/CD pipeline
A: CI/CD is a method to deliver apps to customers by introducing automation:
- Continuous Integration: Developers merge code changes frequently (multiple times daily) with automated builds and tests
- Continuous Delivery: Ensures code can be deployed to production at any time
- Continuous Deployment: Automatically deploys every change that passes tests

Q: What are the best practices for CI/CD?
Q: CI/CD recommendations
A: CI/CD best practices include:
1. Maintain a single source repository
2. Automate the build process
3. Make builds self-testing
4. Keep builds fast
5. Test in a clone of production
6. Make it easy to get the latest deliverables
7. Everyone can see what's happening
8. Automate deployment
9. Monitor pipeline health

# --- ERROR HANDLING / TROUBLESHOOTING ---

Q: How do you handle deployment failures?
Q: What to do if a deployment fails?
Q: Rollback strategies
A: Deployment failure handling involves:
1. Immediate rollback to last stable version
2. Analysis of logs and metrics
3. Identification of root cause
4. Post-mortem meeting with stakeholders
5. Implementation of fixes
6. Update of runbooks and documentation
7. Testing of fixes in staging
8. Gradual rollout of fixed version

Q: Common DevOps problems and their solutions?
Q: DevOps challenges
A: Common DevOps challenges and solutions:
1. Environment drift → Use IaC (Terraform, Ansible)
2. Deployment failures → Implement blue-green/canary
3. Configuration issues → Use config management tools
4. Monitoring gaps → Implement observability stack
5. Security concerns → Shift-left security practices
6. Toolchain complexity → Standardize tooling

Q: What is root cause analysis in DevOps?
Q: RCA process
A: Root cause analysis (RCA) in DevOps involves:
1. Incident detection and documentation
2. Data collection (logs, metrics, traces)
3. Timeline reconstruction
4. Identification of contributing factors
5. Solution implementation
6. Process improvement
7. Documentation updates
Popular RCA methods: 5 Whys, Fishbone diagram, Fault tree analysis

# --- INFRASTRUCTURE AS CODE (IaC) ---

Q: What is Terraform?
Q: Use of Terraform in DevOps?
Q: Infrastructure provisioning
A: Terraform is an open-source IaC tool that:
- Uses declarative configuration files
- Supports multiple cloud providers
- Maintains state of infrastructure
- Enables reproducible environments
- Provides plan/apply workflow
- Supports modules for reusability
- Integrates with CI/CD pipelines

Q: What is Infrastructure as Code?
Q: Define IaC
Q: Benefits of IaC
A: Infrastructure as Code (IaC) is the practice of:
- Managing infrastructure through machine-readable files
- Versioning infrastructure configurations
- Automating provisioning and management
- Ensuring consistency across environments
- Enabling self-documenting infrastructure
- Supporting disaster recovery
Popular tools: Terraform, AWS CloudFormation, Pulumi

Q: How would you secure a DevOps pipeline?
Q: DevSecOps practices
A: Securing a DevOps pipeline involves:
1. Secrets management (Vault, AWS Secrets Manager)
2. Image scanning (Trivy, Clair)
3. Static code analysis (SonarQube)
4. Dynamic application testing (OWASP ZAP)
5. Infrastructure scanning
6. Least privilege access
7. Pipeline approval gates
8. Compliance as code

Q: What is blue-green deployment?
Q: Deployment strategies
A: Blue-green deployment:
- Maintains two identical production environments
- Only one environment serves live traffic
- New version deployed to idle environment
- Traffic switched after validation
- Enables instant rollback
Benefits: Zero downtime, reduced risk, easy rollback

Q: What is canary deployment?
Q: Gradual rollout
A: Canary deployment:
- Releases new version to small user subset
- Gradually increases traffic to new version
- Monitors metrics and performance
- Rolls back if issues detected
- Fully rolls out if successful
Benefits: Risk mitigation, real-user testing

Q: How do you manage secrets in DevOps?
Q: Secrets management
A: Secrets management best practices:
- Never store secrets in code
- Use dedicated secrets managers
- Rotate secrets regularly
- Audit secret access
- Implement least privilege
- Encrypt secrets in transit and at rest
Popular tools: HashiCorp Vault, AWS Secrets Manager, Azure Key Vault
